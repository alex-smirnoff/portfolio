Analysis

The Brief

The project already had approved copy and an overall visual direction. Another designer on our team had created the first version around a purple palette, glassmorphism, and a space-inspired theme.

I was asked to run a quick pre-handoff review and confirm that the design was ready for development. Because I understand front-end implementation, I often handle this final check. I did not expect the review to turn into a full week of redesign work.

The audit uncovered significant structural and interaction issues.

The project was then reassigned to me for completion.

Product Audit

The art direction had a solid foundation.

The main problem was the structure and behavior of the interface:

No responsive behavior was defined.
Several interactive elements communicated the wrong affordance.
Some UX decisions introduced unnecessary navigation and duplicated content.

Reworking the Information Architecture

Before After

The site used three pages where one would have been enough. Beneath the hero, six service cards sat side by side, each with the same CTA leading to the same Solutions page. Repeating a CTA six times gives it disproportionate weight in the user journey, yet the destination only repeated part of the same content and offered no clear path to conversion.

The information architecture exposed a critical gap. The #solutions section led to /solutions, but the shared header's “Get a Quote” CTA targeted a #pricing section that did not exist on that page. No modal behavior had been defined either. A user could show interest, open the details, and lose access to the primary conversion point. Development would have had to invent the missing behavior—either a modal or a jump back to the previous page and down to #pricing.

To solve the issue at its source, I reviewed the content across the cards and pages. The underlying information structure—not just the navigation—needed to change.

The #solutions cards and the /solutions page largely duplicated one another. Each destination card added only a one-sentence explanation—content better suited to an expandable card than a separate page, especially one disconnected from the shared header and reached through six identical CTAs.

I removed the redundant page and added a low-emphasis “Learn more” disclosure to each existing card. The extra copy was secondary—and, in some cases, arguably unnecessary. “Appointment scheduling” already communicates what will be automated. The client wanted to retain the explanation, so I kept it available without letting it compete with the primary content.

The information architecture revealed another structural issue.

The #whyUs section led to /capabilities, where the same shared header again failed to match the page structure. The page introduced an entirely different set of sections that did not justify a separate destination.

The page served a single purpose: presenting the team's capabilities as a card gallery. That gallery fit naturally beneath the automation areas slider. The original flow instead used an oversized logo and another CTA that moved users farther from a conversion point.

I consolidated the content into a standard slider with expandable cards and disclosure controls, then removed the extra page. Users could now evaluate the offering in context instead of navigating through repeated content.

The hero also included a language switcher for a translated site that no longer existed. Client correspondence confirmed that the alternate version had been dropped, so I removed the orphaned control.

The result was a focused one-page site with a clear information architecture:

Interaction and Affordance Fixes

The next major issue was the absence of defined component states and behaviors.

The delivery-stage slider looked polished, but its interaction model was undefined. What exactly should happen when a user selects the right arrow?

Two header items used downward chevrons, but neither the copy nor the layouts explained what they opened, and no expanded states were provided. Because these items simply navigated to page sections, the chevrons created a false affordance.

Button hover and active states were not specified. Without that guidance, implementation often stops at a pointer cursor: the control works, but provides no visual feedback.

I organized the interface into an atomic component system and documented its behavior.

I defined hover and active states for the buttons.

I demonstrated the card slider behavior.

I connected the full navigation flow in the prototype and tested every transition to make sure nothing stalled.

Contact Form UX

The contact form became a separate design track. The “Get a quote” CTA communicated the action, but several parts of the flow remained unclear:

What happens after submission?
How will the user receive the quote?
What happens to the entered data if the request cannot reach the server because the user is offline?
How should text behave inside the form?

The interaction issue applied here as well.

In the redesign, I used the heading to close those information gaps and clarified that a specialist would contact the client shortly after submission. I defined success, failure, and default states for the form, plus default, hover, focus, and filled states for each field.

UI Design

UI Decisions

The contact form was the only major visual weakness. Its geometry was technically aligned, but its visual weight was not: purple labels pulled the composition to the left while white fields disappeared into the white background and the purple button sat alone below.

This was also the site's primary conversion point for an AI startup. The conservative white-field treatment lacked the energy and emphasis needed to draw attention and invite interaction.

I rebalanced the form as a space-inspired composition with neon gradients and subtle liquid-glass details.

The broader visual direction already fit the client's goals. Liquid-glass panels, purple gradients, restrained glow, and space-inspired details reflected the company's focus on AI-powered automation.

I refined the system to make that direction more consistent.

The existing neon and glass accents were too sparse to sustain the intended atmosphere.

BeforeAfterReason for change

Flat buttons weakened the soft glow that gave the composition depth and polish. I replaced them with gradient-filled controls that reinforced the space-inspired visual language.

I added background gradients to create depth and atmosphere. The original flat fills and abrupt transitions had made the space theme feel less immersive.

Creating artwork for the automation-area cards became a project of its own. I used ComfyUI, a node-based AI image-generation workflow that allows direct control over denoising, CFG, sampling, and other parameters. I generated the images with SDXL and used IP-Adapter to carry the site's visual language into each subject. After several rounds of tuning, I finished the assets in Photoshop. The final series shares a consistent purple-blue, neon-glass texture that feels distinctive, engaging, and appropriately technical.

When the client saw the final visual, they said, “Wow, this captures our AI specialization so well. Thank you!”

Responsive Design Gaps

The original design's biggest weakness was its incomplete responsive logic.

In the hero, for example, the original 1224 px layout placed text over the central image and compromised readability, while the tablet layout left excessive space on both sides. The “From Idea to AI” composition had the opposite problem: shifting Atlas 200 pixels left would make the artwork unreadable, yet responsive cropping behavior had never been defined. A developer should not have to invent those decisions.

I rebuilt the responsive system from the ground up. I retained the inherited 1920 px breakpoint and defined continuous behavior from 4K displays down to 350 px screens.

Development

Developer Handoff

The site was now ready for development. I recorded video demos of the interface in action and prepared a detailed handoff note covering layout and animation behavior:

Handoff note

Atlant AI is the landing page of a studio that develops custom digital products based on AI.

The contact form is the site's primary conversion point. Users review the studio's services, capabilities, process, and pricing before submitting their contact information. A manager then continues the conversation with the prospective client.

Figma contains all the necessary assets, component states and responsive layouts. Separate video demonstrations have been added for scenarios that are difficult to clearly convey with static layouts.

Responsive

Demo: CLICK HERE

The responsive layout defines five primary breakpoint states. These are not isolated versions of the page: component behavior is also defined between breakpoints.

The primary range spans 1920 to 350 px. The 1920 px state remains as a legacy wide-screen breakpoint because the original design was started at that width before the project was handed over to me.

All primary frames use Auto Layout. Resizing them directly in Figma shows how components change width, reposition, reflow across columns, or transition into a new composition.

Layout

The main layout logic can be implemented by standard CSS mechanisms: display: flex, gap, flex-wrap, changing flex-direction and responsive sizing.

No hard-coded coordinates are required. Auto Layout expresses the same parent-child relationships that can later be reproduced in CSS.
