Analysis

Initiative

  1. I initiated this project myself—from analyzing the existing process and identifying opportunities to improve it through UX/UI design and front-end implementation of the finished service.
  2. The goal was to reduce manual work in the production of standardized branded materials: business cards, badges, certificates, office plaques, signage, and other template-based assets.
  3. The company regularly produces branded materials from corporate templates. Many requests follow the same pattern: an employee provides personal or organizational data, and a specialist places it into a predefined layout.
  4. As a result, specialists spent a significant share of their time processing repetitive requests instead of developing new design solutions.

Business Analysis

To improve the process, I interviewed the specialists involved in producing branded materials and mapped their workflow in BPMN.

The map showed that even a routine business-card request passed through several people:

Necessity check
Data transfer
Layout preparation
Adjust as needed

Yet much of that work required no design expertise. The following elements were already defined:

Corporate style
Layout structure
Filling rules

The opportunity was clear: move repetitive operations from specialists into the system.

Pain Points

  1. Repetitive operationsThe same steps had to be repeated for every standardized item, no matter how many similar requests had already been completed.01
  2. Multiple specialists involvedProducing a single item required coordination among the requesting employee, internal communications, marketing, and design, extending turnaround time.02
  3. Dependence on specialist availabilityEvery request entered a production queue, so overall capacity depended on how many specialists were available to process it.03
  4. The process could not scale as-isDecentralizing the old process would require design skills, software licenses, and training for every employee—an unreasonable cost for a supporting workflow.04

Turning Business Logic into Algorithms

Based on the findings, I redesigned the process and mapped the new flow in BPMN.

The core solution was an expert system that could handle the repetitive work previously performed by designers and administrative or marketing specialists. A template request can be reduced to structured input, processing rules, and defined output states.

I replaced the back-and-forth communication with a validated form.

JavaScript libraries convert the HTML/CSS template into the required PDF, PNG, or JPEG output.

Design

Product Design: From Algorithms to UX Decisions

Image placeholder

Validated text fields and dropdowns capture each request: users select a department and enter a role, floor, or award category. This replaces email exchanges, removes waiting, and eliminates manual data transfer.

Image placeholder

Dependent dropdowns

Company and address lists contain more than 40 options, so both are searchable. The fields are linked: an address becomes available only after a company is selected, and clearing the company also clears the address. Controlled input standardizes legal entity names, punctuation, abbreviations, and other details that specialists previously checked by hand. This reduces errors in public-facing branded materials.

Image placeholder

Character Counter

Each field has a character limit and visible counter to prevent long values from breaking the layout. The limit includes a practical buffer: the longest recorded job title was 83 characters, while the field allows 130. Users can see the threshold before reaching it and understand why additional input is blocked.

Image placeholder

Live Product Preview

Reviewing the result only after download would force users through repeated edit-download-open cycles, especially when creating several items. Each product therefore includes a live preview that updates as they type and immediately reveals layout or overflow issues. The implementation reuses the same brand-system HTML/CSS template at a smaller scale and connects it to the fields through input events.

Image placeholder

System Status Messages

Validation blocks creation when the email address is missing an @ sign or required fields are incomplete, and the message explains both the issue and the next step. The system also confirms downloads and copy actions. On desktop and tablet, messages appear beside the product; in the mobile layout, they remain fixed at the top of the viewport so they are always visible.

Image placeholder

Download Related Assets

Related assets can be downloaded separately. For example, the dynamic QR code on a business card generates a VCF contact that can be added to a phone after scanning. Users can also save the QR code alone and present it for scanning instead of dictating their contact details.

Development

Development

The service is a client-side web application: core logic, input processing, and interface behavior run without a separate backend. This eliminated the cost of building and maintaining additional server infrastructure.

I hand-coded the entire front end in 2023, when generating a production-ready interface of this complexity with AI was not yet a practical option. The project is therefore more than a UX/UI case: it demonstrates a working knowledge of HTML, CSS, and JavaScript, from page structure and styling to client-side logic and file generation.

Impact

Result

Scaling

In 2025, another company within the same SCM holding commissioned a similar service for business cards and QR codes used in post-sales communication. Because the organizations share the same ultimate ownership, the engagement did not create a corporate ethics conflict. Extending the system to another business validated the concept: it uses resources efficiently and translates business rules into practical product logic and automation.
